# 前端 / 交互约定（Soraika's Hub · Web）

> 这份文件是**需求的唯一落点**：项目 owner 提过的偏好、踩过的坑、以及「为什么这么做」的决定，
> 都记在这里。**每次被指出问题，先在这里补一条**，下次照它做 —— 不靠人反复重复同一句话。
> 与 `Server/CONVENTIONS.md` 并列：那份管后端，这份管界面与交互。

## 0. 最高优先级：视觉与行为先参照旧版

旧版项目在 `D:\Projects\FanJu\soraikas-hub`（与本仓库同级，注意**不是** `Soraikas-Hub-New` 里面）。
配色、尺寸、筛选/多选/下载的交互**先去看旧版怎么做的**，再决定新版怎么写。
不一致时以旧版为基准（除非旧版本身是 bug）。路径读不到就问，**不要猜**。

## 1. 一个状态只用一套视觉语言

- **选中态只给一个主信号**：实底 + 反白（tag chip、字幕组 chip 都用这套）。
  不要再叠「描边 + 浅底 + 强调字色 + 字重」四件套；
- 资源条目选中 = **蓝色外框 + 集数区变蓝**（点整行切换），**不再放复选框与对勾**；
- 判断标准：删掉这个信号，用户还看不看得出来？看得出来就删掉。

## 2. 该做专门控件就做专门控件

- **时刻要做滚轮选择器**（时 / 分两列上下滑，像时钟那样，中间那格是选中值）；
  丢一个原生 `input[type=time]` 了事不行，自绘「时 : 分」两个文本框那种半成品也不行；
- 能被「滑动 / 点选」更好表达的，就做那套交互，别让用户打字。

## 3. 输入要接受人话（单位、格式）

- 时长类**直接写单位**：`10s` / `1.5m` / `2h` / `500ms` / `10分钟`，小数也认（`10.5s`）；
  换算成毫秒由程序做 —— 让人把 10s 心算成 10000 是把机器该干的活推给人；
- **数值 / 时长：行内是完整写法，点开是同一个输入框 + 加减**
  - 行内：时长显示 `350ms` / `1m 30s` / `7d`（`formatDuration`，最多两级单位）；
    其它数值显示「数字 + 字段单位」（`350` + `ms`、`5` + `次`）；
  - **时长的输入框与行外同一套写法**：显示 `1m 30s` 就能照着填 `1m 30s` / `7d` / `1h 30m 5s`
    （不再有「数值 + 单位下拉」两段式 —— 那等于让人自己换算，还容易出现"外面 7d、输入框里 604800000"）；
    写不出单位的纯数字按当前显示单位理解；解析不了就回滚，不发脏值；
  - 点开后 `[−] 输入 [＋]`，支持**鼠标滚轮 + 左右拖动**微调（调个超时不值得"点开—输入—回车"走一遍）；
  - 弹层**与输入框同宽**（`PopoverPanel` 的 `width="anchor"`）。
  - 步长按量级（秒级 1s、分钟级 30s、小时级 5m、次数类 1），别让人按上千次；
- **不要「常用时长」这类预设**：给超时配「7 天」就是笑话。直接写 + 加减 + 滚轮即可；
- 时长文案用 `1s 500ms` / `30s` / `1h 30m` 这种 s/ms/m/h/d 复合写法（最多两级），
  **不加「≈」** —— 它是同一个值的另一种写法，不是估算；
- 同理：时长、字节、评分这类都别让人填基准单位的裸数字。

## 4. 「基础 / 高级」要有，划分要准

- **要保留「基础 / 高级」切换**（别把功能删掉，也别用"折叠块"替代）：
  基础 = 只显示**必要配置**，高级 = 全部；
- 基础模式的判定只有一条：**不填（或不动）会跑不起来 / 必须按自己环境改** → 进基础。
  例：AI 接口地址与 Key、模型名、站点地址、qB 地址与凭据；
  有合理默认值、改它属于**调参**的 → 只在高级里。例：超时、TTL、并发间隔、UA、落盘目录、失败退避；
- **基础模式里不许塞 advanced 项 —— 哪怕它被改过**（"改过的也显示"会让基础悄悄变成全部，
  使用者就会问"为什么基础里还有每条间隔"）；
- 被收起的项里有改过的，就在顶栏「高级」按钮上挂**角标**（`高级 ③`）交代，别让人找不到自己改过什么；
- 基础模式现在就是这 9 项：`mikan.bases` / `bgm.bases` / `ai.baseUrl` / `ai.apiKey` / `ai.model` /
  `worker.dailyAt` / `worker.fetchSubgroups` / `qb.base` / `qb.apiKey`；
  **`verify-settings` 有断言钉住"基础项 ≤ 10 且必须是这几项"**。

## 5. 导出只留一个入口

- 导出 = **含密钥的完整备份**（换地方导入就能接着用）；
- 不再摆「导出 / 导出（含密钥）」两个按钮让人先做选择，也不导"脱敏版"这种没法用的东西；
- 安全提醒放 `title`（别外传），而不是拆成第二个按钮。

## 6. 实现细节对使用者静默

- 不显示「已写入数据库 N 项」这类记账提示，也不要人点「全部写入数据库」；
- 该做的事（落库、补齐、缓存）在后台静默完成，使用者不必知道它存在；
- 页面不出现 `.env`、`npm run`、端口、进程这类开发者词汇（那是文档的事）；
- **测试连接的反馈**：成功只说「**成功 · 1/2 可用 · 681ms**」（绿），不要把 `200` 这种状态码甩给使用者
  （他知道绿色=通了就够）；失败才给具体原因（含状态码，便于排错）；
- **「通」的标准按服务定，不是「状态码 200 就成功」**：AI 要**真跑一次对话**
  （system 让它只回 `SORAOK`，**收到这个词**才算通 —— 连带验证了模型名与"会不会听指令"），
  下载要**真拿到版本号**（`/api/v2/app/version` 返回 `v5.1.2`；未认证的 403 说明「Key 不对」而不是「通了」）。
  地址填对但 Key 错 / 模型名不存在时若报「通」，用户会以为配好了，等真去解析资源才炸；
- **时间单位统一成毫秒（`*Ms`）**，界面一律用 `utils/duration.js#formatDuration` 显示：
  `350ms` / `30s` / `1m 30s` / `7d` / `1d 12h`（最多两级单位，除不尽才退到毫秒）。
  不再有「值是小时 / 秒」的例外项 —— 那种例外正是"24 小时被显示成 24ms"的来源；
  新增时长项时：**存毫秒**、**挂 `format: 'duration'`**、路径以 `Ms` 结尾；
- **时长行直接显示完整时长文案，不再挂单位胶囊**：值里已经带单位（`7d`），
  再挂个胶囊就是重复；非时长数值仍是「数字 + 字段单位」（`5` + `次`）；
- **滚轮控件必须自己接管滚轮**：浏览器一次 `wheel` 的 `deltaY` ≈ 100px ≈ 3 格，
  而 `scroll-snap` 只在滚动**停下后**吸附 —— 于是「滚一下跳四个」，根本选不准。
  解：`@wheel.prevent` 手动 `scrollTop += ±一格`；另外原生滚动区鼠标拖不动，要自己用
  pointer 事件（`setPointerCapture`）按位移改 `scrollTop`，并在拖拽后压住那次误触发的 `click`；
- **「显示单位」和「步长」必须互相约束**：单位是按「能不能整除」推导出来的
  （`60000` → `m`、`350` → `ms`），所以**步长必须是当前单位的整数倍**（显示 `m` 就 ±1 分钟）。
  步长若按"量级"另搞一套（分钟级给 30 秒），滚一下就会得到除不尽的值 → 单位退到 `s`、
  数字暴涨（`30 m` → `1830 s`），再滚一下凑巧整除又跳回 `m`（`31 m`）—— 数字和单位一起抖，
  用户只会说"这是坏了"。凡是「A 的显示依赖 B」的地方，都要保证 B 的变化不破坏 A 的前提；
- **长生命周期对象不能闭包住配置值**：缓存实例是模块加载时创建的，若把 `ttlMs: config.xxx`
  这样**传死值**，设置页改完就永远用旧值（界面上"保存成功"，实际要重启进程才生效）——
  实测踩到过（标签缓存 / 集数缓存）。修法：`ttlMs` 传**函数**（`() => config.xxx`），
  写入时按当下配置取；凡是「模块级单例 + 读配置」的地方都照此办理，
  能不标 `restart` 就别标 —— 标了就等于告诉用户"你改的东西暂时没用"；
- **界面显示单位 ≠ 入库单位**：设置项的数值**一律以毫秒入库**，界面按最顺的单位显示
  （`600000` → `10 m`）。提交必须换算回去（`commitEdit` 走 `unitFactor`），
  否则"1 分钟的缓存"会被存成 `1` 毫秒 = 永远不缓存；

  换库 / 重建后 id 全变，磁盘上抓好的几百张图瞬间成孤儿（实测 469 条里 313 条如此：
  文件都在、体积也正常，但按 id 找不到 → 每次访问都重新回源，缓存等于不存在）。
  另外命中要**先查磁盘**再信数据库字段（字段可能为空/过期），旧命名的文件要能迁移过去；
- **回源拿到二进制必须先校验内容再落盘**：图床防盗链 / 图片失效时返回的是 **200 + HTML**，
  `res.ok` 挡不住。按 magic bytes 判断，并顺带得到**真实**扩展名（URL 后缀不可信：
  `/images/x.jpg?width=400`、Bangumi 的 hash 名都要靠内容判断）；
- **按钮不要因为「没事可做」就灰掉**：灰按钮不告诉人为什么点不动。让它能点，
  点完回一句「**无变化 · 已是最新**」—— **蓝色**（成功是绿、失败是红，无变化用蓝，别用灰字），
  按钮本身也染蓝，2 秒复原。人就知道是「已是最新」，而不是「按钮坏了」。

## 7. 窄容器（340px 面板）里的按钮

- 只放**图标** + `title` / `aria-label`，不带文字（面板里带文字必然换行）；
- 按钮组 `flex-shrink: 0` **整体不拆行**；空间不够时让旁边的文本组（`.facts`）先换行；
- 预留 / 未接入的按钮用 `aria-disabled`，**不要用 `disabled`** —— 浏览器在 disabled 元素上
  不显示 `title`，鼠标放上去连「为什么点不了」都看不到。

## 8. AI 标签（照旧版）

- AI 只产出「给人看的 display」；**实际匹配用从文件名逐字摘抄的写法**（字符串包含、大小写不敏感）；
- 同类型 OR、跨类型 AND，用 AND/OR 连接词画出来，不让用户切模式；
- 命中标签多的排前面（旧版 matchScore）；
- 「单集 / 合集」切换**只在资源里真有合集时出现**（否则是点了必然为空的假控件）；
- **修订版单独处理**：字幕组修版重发的叫法五花八门（`v2` / `V2` / `ver.2` / `第N版` /
  `修正版` / `Rework` / `Repack`），在**后端**归一成 `revision` 数字（`lib/format.js` 的 `revisionOf`），
  资源条目带 `item.revision`（1 = 原版）；标签区把它们合成**一个**「修订版」标签。
  它的语义是 **优选（PREFER）**：同集有修订就用修订、**没有修订的集照旧保留**（只换版、不筛除）。
  - 已选区里画成 `PREFER 修订版`（**不是 AND**，免得让人以为"没修订的集会被筛掉"）；
  - 算法在 `utils/episode.js` 的 `dedupeLatestRevisions`：同集取最高版，同集同版本的多条都留
    （720P/1080P 不是版本关系），合集与识别不出集号的不参与；
  - 术语别用错：这不是 XOR（XOR 是"二选一"），是**分组择优 / 优先版本**（priority、prefer）。
- **整体特征由规则算，不问 AI**：是**简报**不是报表 —— 「更新至第 25 话」「含 2 个合集包」
  「**共 N 条资源**」（兜底，永远有，保证这块不空着）；分类维度（分辨率/字幕）**多于 1 种才列**，
  **不带 ×N 计数**（`1080P × 30 / 720P × 17` 那种没人读）；
  **算不出集数也不空着** —— AI 说"没有可筛维度"（整批格式一致）时照样有内容；
- **「没有可用的筛选标签」这种文案要改**：说清原因 ——「这批资源格式一致，没有可筛的维度」；
- **它的显示不受 AI 状态影响**：AI 没配、解析失败、这批资源没有可用标签时，快速信息要照常显示
  —— 规则算出来的东西被 AI 的状态吞掉，逻辑上就不通。

## 9. 字幕组（Mikan）

- 两个 id 别混：
  - `div.subgroup-text[id]` = **RSS 分组 id** → **请求资源列表用它**（实测：用它 5 条、用发布组 id 0 条）；
  - `/Home/PublishGroup/{id}` = **发布组 id** → 全站身份，**用来去重**；
- **字幕组不落库**（2026-10 变更）：`/subgroups` **每次直接问 Mikan 详情页**，返回的 `id` 就是
  **该作品下的 rss id**，取资源时原样回传（`/releases?subgroupId=<id>`）。
  库里只保留一张 `subgroup` **名字字典**（`mikan_subgroup_id` 唯一）；**`anime_subgroup` 已删除**
  —— 原因见 `Server/docs/ARCHITECTURE.md` §7-14。

## 10. 尺寸与配色（旧版基准）

- 集数区：**56px 竖条 + 1.55rem 斜体衬线暖金数字**；合集是范围（01-12）降一档 0.95rem；取不到显示 `—`；
- tag 类型色：分辨率蓝 / 编码紫 / 字幕绿 / 片源橙 / 合集青 / 其它灰（`tokens.css` 的 `--tag-*`），
  选中 = **实底该色 + 反白字**；
- 颜色一律走令牌，组件里不写十六进制。

## 11. 后端给成品字符串，前端不格式化

- 评分固定一位小数由后端给（`scoreText`），前端连 `toFixed` 都不写；
- 卡片与详情必须用同一份字符串（口径分叉是最容易犯的错）。

## 12. 面板与页面

- 切到别的页面**自动收起**详情面板（数据保留，切回首页点开是秒出、不重新请求）；
- 面板里的区块（评分卡 / 简介 / 外链 / 字幕组 / AI 位 / 资源列表）一律包 `section.card`，
  左右边界由同一份卡片内边距决定，不允许裸元素参差；区块标题统一用全局 `.block-title`；
- **资源条目 = 三行**：标题 / 元信息（`465.5 MB · 09-12 00:30`，`·` 由 CSS 加）/ **操作条**；
  - 操作条是 `磁力 / 种子 / 下载` 三等分**铺满整行**（不是挤在右侧留一片空白），按钮带文字不用 hover 猜；
  - 按钮数不定时（没磁力/没种子）自动两等分 —— 用 `grid-auto-flow: column; grid-auto-columns: 1fr`；
- **资源头部 = 左信息 / 右操作**：左边「计数 · 全选 · 已选 N / 总数」，右边「下载」；
  宽就一行、窄了让**操作组整组**换到下一行（`flex-shrink: 0`，不许一个个按钮掉下来）；
- 下载按钮**只有一个**：没筛 = `全部下载 (N)`、筛过 = `下载筛选结果 (N)`；选中后多一个 `下载选中 (N)`；
- 多选：**一个按钮切换「全选 ↔ 取消全选」**，范围 = 当前筛选结果（含还没渲染出来的那些）；
  判"是否全选"用 `Set`，别对几百条做 `includes`。

## 13. 改数据结构时，模板里的循环变量要一起改

- 这次踩过：把 `group.sections` 改成 `group.blocks` 后，内层漏改了一处
  `v-for="field in section.fields"` —— 渲染时变量不存在，**渲染函数抛错，页面卡在加载态**；
- 验收必须同时盯两头：
  1. **数据结构断言**（`store.groups[].blocks[].fields` 都在）；
  2. **模板变量一致性**（不残留 `in section.xxx` 这类旧名）；
- SSR 首帧没有数据、不渲染卡片，**单靠 SSR 渲染测不到这类 bug**，要专门写结构断言。

## 14. 改动要能验收

每处改动在 `Web/scripts/verify-e2e.mjs`（必要时 `Server/scripts/verify-*.mjs`）都有对应断言，
收尾必须跑：

```bash
cd Server && npm run verify
cd Web && npm run build && npm run verify:e2e
```

临时调试脚本与日志**用完即删**，不留在 `scripts/` 里。

## 16. 识别规则要覆盖各家写法，提示词别写死

- **集数**：**主要交给 AI 逐条解析**（`Web/src/composables/useEpisodes.js` → `/api/ai/classify/episodes`），
  列表徽标、单集/合集切换、"更新至第 N 话"全部优先用 AI 的结果；前端规则**只做兜底**
  （没配 AI / 失败 / 某条为空时才用）。文件名写法永远补不完：
  `- 1180 (B-Global 3840x2160 …)`（**4 位集号**，长篇）、`S01E12`、`第1180集`、`[04v2]`…
  兜底规则也要覆盖这些写法，并且**位数别写死**（曾经限制 1-3 位，把 `- 1180` 整条漏掉）；
- **误判防护也要有测试**：`1080p` / `WEB-DL` / `AVC` / `x264` 都不许被当成集号或版本号；
- **AI 提示词别写「整批一样就别返回」**：那会让"只有一条资源 / 整批同格式"时一个标签都没有，
  界面上看着像"什么都没识别出来"（其实是模型老实执行了指令）。
  正确做法：照样返回并标 **`all: true`**，由界面当**只读特征**展示（不做可点筛选项），
  和"更新至第 N 话 / 共 N 条资源"并排 —— 这样"这批都是 WEB-DL 1080p"这类信息也看得见。
- **解析批次与展示同步**：一批 = `ReleaseList` 的 `PAGE_SIZE` = 面板的 `AI_BATCH`（**120**）。
  首屏解析前 120 条；用户点「显示更多」（+120）时**只把新增的那一段**发出去解析，
  结果**累加**（同名标签 `match` 取并集、`all` 取与）—— 不重来、不重复花钱。
  **后端绝不 `slice(0, maxTitles)` 截断**：用户不知道被截了，界面就会像"怎么就这么点标签"。
  `ai.maxTitles` 是**单批上限**，超出就切多批并发跑完（防一次 prompt 过大）；
  `all`（整批一致）按**全量**重算 —— 单批的判断覆盖不了全部资源；
- **标签要过一遍去重**（`dropCovered`）：模型爱同时给 `HEVC` 与 `HEVC-10bit`、`简繁内封` 与
  `简繁内封字幕` —— 后者只是加了后缀，点它筛出来的东西前者都能筛，是纯噪音。
  规则：同类型下「写法被别的标签覆盖」的删掉（要求对方名字更短，避免互删）；
  但**必须带作品上下文**（番剧名 / 季）—— 模型得知道自己在分析什么，才分得清字幕组名与片源；
  `all`（整批一致）由**后端按这批数据重算**（写法命中每一条才算 `all`），不信单次模型的判断。

## 17. 验收别留下孤儿进程（会让电脑越用越卡）

- Windows 下 `child.kill()` **不保证杀掉子进程树**：verify 反复跑会攒出「没监听任何端口的
  裸 server」常驻（实测一次 107MB），表现为「电脑越用越卡」；
- 跑完验收顺手看一眼：
  `tasklist /fo csv /nh | findstr /i node.exe`
  多余的用 `taskkill /PID <pid> /T /F` 清（`/T` 是关键，杀整棵树）；
- 另外 `npm run dev` 本身占 300–400MB（vite ≈250MB + server watch ≈100MB），属正常；
  觉得卡就 Ctrl+C 重启一次 dev，把 `--watch` 累下来的旧进程一起收掉。
